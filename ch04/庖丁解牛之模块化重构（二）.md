## 4.2 庖丁解牛：基于 main.py 的重构

这一节的目标是把第3卷的 ch03/main.py拆分成以下结构：

```text
ch04/

├── nn/                    ← 神经网络算子库（基础法阵）
│   ├── __init__.py        ← 统一导出口
│   ├── conv.py            ← 卷积三件套 Conv + autopad
│   └── block.py           ← 构建块 Bottleneck, C2f, C3k2, SPPF
├── model.py               ← 模型定义（法器）
├── dataset.py             ← 数据集管理（灵矿仓库）
├── trainer.py             ← 训练引擎（司炉中枢）
└── main.py                ← 入口
```

各文件只负责一件事：

| 文件 | 职责 |
| --- | --- |
| `nn/conv.py` |  定义最基础的卷积算子 |
| `nn/block.py` |用卷积算子搭建更高级的构建块 |
| `nn/__init__.py` | 统一导出网络算子，让外部用 `from nn import Conv` 就能导入算子 |
| `model.py` | 用算子和构建块组装完整的检测模型   |
| `dataset.py` |  管理数据的创建、加载、打包       |
| `trainer.py` | 管理训练循环、验证、权重保存   |
| `main.py` | 一键启动入口 |

接下来我们逐一创建这些文件。请新建一个 `ch04/` 文件夹，然后在里面新建一个 nn/ 子文件夹。我们从最底层的算子开始，逐层向上搭建。

### 4.2.1 第一步：拆出数据层 `dataset.py`

你可能好奇，为什么先拆 dataset.py 而不是 nn/？

原因很简单：数据集模块是所有模块中最独立的一个。它不依赖模型、不依赖训练器、不依赖任何自定义算子。它只用了PyTorch自带的 Dataset 和 DataLoader。从最独立的模块下手，能让我们最直观地感受"拆分"的过程——把原来 main.py 中的一段代码原封不动剪切出来，放到新文件里。

打开第3卷的 main.py，找到 MultiscaleFakeDataset类 和 collate_fn方法。这段代码和模型定义、训练逻辑没有任何关联——它只负责生成虚假数据。这就是天然的切割线。

现在，在 ch04/ 下新建 dataset.py，写入以下内容。

首先是文件头部的文档字符串和import语句：

```python
"""
数据集定义 (dataset.py)
对标: ultralytics/data/dataset.py 中的 YOLODataset

职责：

  - 数据集的创建与管理
  - 标签的加载与预处理
  - collate_fn 多目标打包
  - 目前仍使用虚拟数据（后续将替换为真实 DOTA 数据集）。
"""

import torch
from torch.utils.data import Dataset, DataLoader

```
注意 `import` 的两种不同写法。

要专门提醒一下，在切分文件的时候，千万不要忘记补上合适的 `import` 语句。

`dataset.py` 中的两个 `import` 全部来自 `PyTorch` 标准库——零外部依赖。这就是高内聚低耦合的极致，数据模块不需要知道模型长什么样。

文档字符串里有两行关键信息：

- 对标 `ultralytics/data/dataset.py`——每个文件都标注它在Ultralytics官方代码库中的对应位置，这样方便从一开始就建立"我的代码 → 官方代码"的映射。

- 后续演进路线——虚拟数据只是暂时的，后续逐步接入DOTA8真实数据，升级为完整数据集。

接下来是数据集类，代码基本可以从第3卷的代码中粘贴过来，本节就不再详细解释了，但是为了方便对照，还是把完整的代码贴出来：

```python
class MultiscaleFakeDataset(Dataset):
    def __init__(self, num_samples=100, img_size=256, num_classes=2):
        super().__init__()
        self.images = []
        self.targets = []

        channels = num_classes + 8
        grid_sizes = [img_size // 8, img_size // 16, img_size // 32]

        for _ in range(num_samples):
            image = torch.randn(3, img_size, img_size)
            target_list = [torch.randn(channels, gs, gs) for gs in grid_sizes]

            self.images.append(image)
            self.targets.append(target_list)

    def __len__(self):
        return len(self.images)

    def __getitem__(self, idx):
        return self.images[idx], self.targets[idx]
        
        
def collate_fn(batch):
    images = torch.stack([item[0] for item in batch])
    targets = [torch.stack([item[1][s] for item in batch]) for s in range(3)]
    return images, targets
    
```

到这里还没有完。

我们还需要写一个 `build_dataloader` 函数，这是一个工厂函数，能够根据需要创建合适的DataLoader。`build_dataloader`的代码如下，请把他加入到新建 `dataset.py` 文件中:

```python
def build_dataloader(dataset, batch_size, shuffle=True):

    """
    DataLoader 的工厂函数。
    对标: ultralytics/data/build.py::build_dataloader
    """
    return DataLoader(
        dataset,
        batch_size=batch_size,
        shuffle=shuffle,
        collate_fn=collate_fn,
        drop_last=False,
    )
```

为什么要包一层工厂函数，而不是直接在 main.py 里写 DataLoader(...)？

因为随着项目演进，创建DataLoader的逻辑会越来越复杂——比如后续要修改为 InfiniteDataLoader，为模型训练提供源源不断的数据，要加分布式采样器等等。如果每次都在 main.py 里改，入口文件就会越来越臃肿，也违背了“高内聚，低耦合”的原则。

用工厂函数把创建逻辑封装起来，`main.py` 永远只需要调用一行 build_dataloader(...) 就行，合适的DataLoader就会被创建出来。

这就是低耦合的威力—— `main.py` 不需要知道DataLoader的创建细节，它只需要知道"调用 build_dataloader 就能拿到一个可用的DataLoader"。

### 4.2.2 第二步：算子库的诞生

接下来处理 `nn/` 目录。这是最关键的拆分——把算子从 `main.py` 中剥离出来，形成一个可复用的算子库。

回忆第3章，我们在 `main.py` 中定义了五个算子：`autopad`、`Conv`、`Bottleneck`、`C2f`、`C3k2`、`SPPF`。这些算子有两个特点：

- 它们是基础设施，不只是当前模型在用——后续几乎任何模型都会用到 Conv 和 C3k2。

- 它们有内部依赖关系：C3k2 → C2f → Bottleneck → Conv → autopad。

把它们从模型定义中剥离出来，放进专门的 nn/ 目录，就像把通用法阵从某一款法器的图纸中抽出来，放进"标准法阵库"。以后打造任何法器，都可以直接从库里取。



#### 1. `nn/conv.py`：基础卷积算子

在 `ch04/nn/` 目录下新建 `conv.py`文件。这个文件只包含两样东西：autopad 函数和 Conv 类。可以从第3卷的main.py文件中将这两部分的代码拷贝过来，但是不要忘记加上说文档说明，并导入必要的依赖包。

```python
"""
基础卷积算子
对标：ultralytics/nn/modules/conv.py
"""
import torch.nn as nn

def autopad(k, p=None, d=1):
    """自动计算 same padding。"""
    if d > 1:
        k = d * (k - 1) + 1

    if p is None:
        p = k // 2

    return p


class Conv(nn.Module):

    """标准卷积: Conv2d + BatchNorm2d + SiLU"""
    default_act = nn.SiLU()
    def __init__(self, c1, c2, k=1, s=1, p=None, g=1, d=1, act=True):
        super().__init__()
        self.conv = nn.Conv2d(
            c1, c2, k, s,
            autopad(k, p, d),
            groups=g, dilation=d, bias=False
        )
        self.bn = nn.BatchNorm2d(c2)

        self.act = (
            self.default_act if act is True
            else act if isinstance(act, nn.Module)
            else nn.Identity()
        )

    def forward(self, x):
        return self.act(self.bn(self.conv(x)))

    def forward_fuse(self, x):
        return self.act(self.conv(x))
```

这里不再重复解释 BN、SiLU 和 `autopad` 的原理。它们已经在第 3 章完成，现在只是把代码搬到独立文件。

#### 2. `nn/block.py`：高级构建块

`Bottleneck`、`C2f`、`C3k2`、`SPPF` 都依赖 `Conv`，统一放进 `block.py`，在 `ch04/nn/` 目录下新建 `block.py`文件，在其中输入说明，并导入必要的库。

```python

对标：ultralytics/nn/modules/block.py
"""

```
注意最后一行：`from .conv import Conv`。这里的 `.conv` 表示"当前包（nn/）里的conv模块"。这就是Python的相对导入。`block.py` 依赖 `conv.py` 里的 `Conv` 类——这是合理的，因为它们在同一个包里，服务于同一个目标（提供算子）。

接下来，把第3卷中main.py文件中的`Bottleneck`、`C2f`、`C3k2`、`SPPF` 依次拷贝过来。

```python   
class Bottleneck(nn.Module):
    """
    YOLO 风格 Bottleneck：
    两个 Conv + 可选残差连接

    参考：
    ultralytics/nn/modules/block.py::Bottleneck
    """

    def __init__(self, c1, c2, shortcut=True, g=1, k=(3, 3), e=0.5):
        super().__init__()

        # 中间通道数
        c_ = int(c2 * e)

        self.cv1 = Conv(c1, c_, k[0], 1)
        self.cv2 = Conv(c_, c2, k[1], 1, g=g)

        # 只有输入输出形状一致时，才能直接做 x + F(x)
        self.add = shortcut and c1 == c2

    def forward(self, x):
        y = self.cv2(self.cv1(x))

        if self.add:
            return x + y

        return y
        
        
class C2f(nn.Module):
    """CSP Bottleneck with 2 convolutions."""

    def __init__(self, c1, c2, n=1, shortcut=False, g=1, e=0.5):
        super().__init__()
        # 定义网络中需要用到的各个模块，包括分流前调整通道的cv1和最后融合数据的cv2，
        # 以及包含n个Bottleneck的复杂处理结构
        self.c = int(c2 * e)
        self.cv1 = Conv(c1, 2 * self.c, 1, 1)
        self.cv2 = Conv((2 + n) * self.c, c2, 1)
        self.m = nn.ModuleList(Bottleneck(self.c, self.c, shortcut, g, k=(3, 3), e=1.0) for _ in range(n))

    def forward(self, x):
        y = list(self.cv1(x).chunk(2, dim=1))

        for m in self.m:
            y.append(m(y[-1]))

        return self.cv2(torch.cat(y, dim=1))
        
        
class C3k2(C2f):
    """C3k2：当前使用 Bottleneck 作为内部特征提取单元。"""
    def __init__(self, c1, c2, n=1, c3k=False, e=0.5, g=1, shortcut=True):
        super().__init__(c1=c1, c2=c2, n=n, shortcut=shortcut, g=g, e=e)
        
        
class SPPF(nn.Module):
    """Spatial Pyramid Pooling - Fast."""

    def __init__(self, c1, c2, k=5):    
        super().__init__()        
        # 隐藏通道：先压缩到输入通道数的一半
        c_ = c1 // 2

        # 调整通道数
        self.cv1 = Conv(c1, c_, 1, 1, act=False)

        # 四路特征拼接后，再进行融合
        self.cv2 = Conv(c_ * 4, c2, 1, 1)

        # 5×5 最大池化，stride=1，因此不改变特征图尺寸
        self.m = nn.MaxPool2d(kernel_size=k, stride=1, padding=k // 2)

    def forward(self, x):
        x0 = self.cv1(x)

        y1 = self.m(x0)
        y2 = self.m(y1)
        y3 = self.m(y2)

        y = torch.cat([x0, y1, y2, y3], dim=1)

        return self.cv2(y)
```

从现在开始，`model.py` 不需要再定义这些算子，只需要调用它们。

#### 3. `nn/__init__.py`：统一导出口

最后给 `nn/` 加一个统一入口，这是整个 nn/ 包的"门面"。

在 ch04/nn/ 下新建 ` __init__.py`文件，并输入：

```python
"""
nn：神经网络基础算子库
"""
from .conv import Conv, autopad
from .block import Bottleneck, C2f, C3k2, SPPF

__all__ = [
    "Conv",
    "autopad",
    "Bottleneck",
    "C2f",
    "C3k2",
    "SPPF",
]
```

这个文件极其简短，但作用巨大。有了它，外部代码可以直接写：

```python
from nn import Conv, C3k2, SPPF
```
而不用关心这些类具体放在哪个文件中，所以导入模块时就不用写：
```python
from nn.conv import Conv
from nn.block import C3k2, SPPF

```
这就是统一导出口的价值——对外只暴露一个入口，内部怎么组织文件是"nn包的私事"。如果将来我们把 `SPPF` 从 `block.py` 移到单独的 `pool.py` 里，外部代码完全不需要改动，只需要修改 `__init__.py` 的import路径。


`__all__` 列表声明了"这个包对外公开哪些名字"。虽然不写也能用，但这是一个良好的工程习惯——它告诉其他开发者"这些是公开API，其他的是内部实现细节"。

>炼器笔记：当一个目录下有 __init__.py 文件时，Python就把这个目录当成一个"包"（Package）。
>
>from nn import Conv 的执行过程是：1. Python找到 nn/ 目录，2. 执行 nn/__init__.py，3. __init__.py 中的 from .conv import Conv 把 Conv 导入到 nn 命名空间，4. 外部代码就能通过 from nn import Conv 拿到它

### 4.2.3 第三步：重塑模型 (model.py)

算子库就绪了。现在我们来定义模型——把第3卷 `main.py` 中的 `YOLOLikeDetector` 类抽出来，放进独立的 `model.py`文件中。在 `ch04/` 下新建 `model.py`。有了 `nn/` 算子库以后，模型文件就只负责一件事：

> **使用现成算子，组装完整网络。**

`model.py`中的代码如下，首先添加导入模块的语句，然后将 `YOLOLikeDetector`类的代码拷贝过来。

注意 `from nn import Conv, C3k2, SPPF` 这一行——这就是我们刚才搭建的 `nn/` 包在发挥作用。`model.py` 不需要知道 `Conv` 在 `nn/conv.py` 里，`C3k2` 在 `nn/block.py` 里。它只需要向 nn 包索取所需的零件就可以。

```python
"""
模型定义
对标：ultralytics/nn/tasks.py 中的 DetectionModel
"""
import torch
import torch.nn as nn
from nn import Conv, C3k2, SPPF
        
class YOLOLikeDetector(nn.Module):
    """使用核心算子搭建模型。"""

    def __init__(self, num_classes=2):
        super().__init__()
        self.out_channels = num_classes + 8

        # ---------------- Backbone ----------------
        self.stem = Conv(3, 16, 3, 2)             # 256 -> 128
        self.down1 = Conv(16, 32, 3, 2)           # 128 -> 64
        self.stage1 = C3k2(32, 32, n=1)

        self.down2 = Conv(32, 64, 3, 2)           # 64 -> 32
        self.stage2 = C3k2(64, 64, n=1)           # P3, stride=8

        self.down3 = Conv(64, 128, 3, 2)          # 32 -> 16
        self.stage3 = C3k2(128, 128, n=1)         # P4, stride=16

        self.down4 = Conv(128, 128, 3, 2)         # 16 -> 8
        self.stage4 = C3k2(128, 128, n=1)
        self.sppf = SPPF(128, 128)                # P5, stride=32

        # ---------------- Neck：沿用第2卷 FPN ----------------
        self.up = nn.Upsample(scale_factor=2, mode="nearest")

        self.lateral5 = Conv(128, 64, 1, 1)
        self.fpn4 = C3k2(192, 64, n=1)            # 64 + 128 = 192

        self.lateral4 = Conv(64, 32, 1, 1)
        self.fpn3 = C3k2(96, 32, n=1)             # 32 + 64 = 96

        # ---------------- 临时预测头 ----------------
        self.head3 = nn.Conv2d(32, self.out_channels, 1)
        self.head4 = nn.Conv2d(64, self.out_channels, 1)
        self.head5 = nn.Conv2d(128, self.out_channels, 1)

    def forward(self, x):
        # Backbone
        x = self.stem(x)                          # [B, 16, 128, 128]
        x = self.down1(x)                         # [B, 32, 64, 64]
        x = self.stage1(x)                        # [B, 32, 64, 64]

        x = self.down2(x)                         # [B, 64, 32, 32]
        p3 = self.stage2(x)                       # [B, 64, 32, 32]

        x = self.down3(p3)                        # [B, 128, 16, 16]
        p4 = self.stage3(x)                       # [B, 128, 16, 16]

        x = self.down4(p4)                        # [B, 128, 8, 8]
        x = self.stage4(x)                        # [B, 128, 8, 8]
        p5 = self.sppf(x)                         # [B, 128, 8, 8]

        # FPN：P5 -> P4
        up5 = self.up(self.lateral5(p5))          # [B, 64, 16, 16]
        f4 = torch.cat([up5, p4], dim=1)          # [B, 192, 16, 16]
        f4 = self.fpn4(f4)                        # [B, 64, 16, 16]

        # FPN：F4 -> P3
        up4 = self.up(self.lateral4(f4))          # [B, 32, 32, 32]
        f3 = torch.cat([up4, p3], dim=1)          # [B, 96, 32, 32]
        f3 = self.fpn3(f3)                        # [B, 32, 32, 32]

        # 三尺度输出
        return [
            self.head3(f3),                       # [B, C, 32, 32]
            self.head4(f4),                       # [B, C, 16, 16]
            self.head5(p5),                       # [B, C, 8, 8]
        ]
        
```

这段网络结构并没有改变。我们只是把“算子”和“模型”分开。

将以上代码完整写入 ch04/model.py。写完后，**在命令行进入 `ch04/` 目录并启动Python解释器**，在Python解释器中快速验证一下：

### 4.2.4 第四步：司炉中枢 (trainer.py)：从函数到类的跳跃

模型负责“怎么算”，训练器负责“怎么练”。

最后一个文件 `trainer.py`。它封装了完整的"训练-验证-保存"流程。在 `ch04/` 下新建 `trainer.py`，写文档说明，导入必要的模块，这个步骤你应该已经比较熟练了。

```python
"""
训练器 (trainer.py)
对标: ultralytics/engine/trainer.py 中的 BaseTrainer
本文件职责：
  - 管理训练超参数
  - 执行训练循环 (train loop)
  - 调用验证逻辑
  - 保存模型权重 (last.pt / best.pt)
后续演进路线:
  - Loss 替换为 v8OBBLoss
  - 验证替换为完整的 Validator
  - 加入 EMA、AMP、学习率调度器
"""

import os
import torch
import torch.nn as nn
import torch.optim as optim
from tqdm import tqdm
```

注意 `trainer.py` 的`import`——它不`import`任何我们自己写的模块。它不依赖 `nn/` 里的算子，也不依赖 `dataset.py`。它只需要`PyTorch`标准库和 `tqdm` 进度条库。

为什么？因为 `Trainer` 的职责是"管理训练流程"，它接收一个已经创建好的模型和 `DataLoader`，也就是说，模型、数据都是通过参数传递给它的，因此它不需要知道模型是怎么搭建的、数据是怎么加载的。这就是低耦合。

第 3 卷中的训练逻辑全部塞在 `train_model()` 方法里。它既创建 Loss 和 Optimizer，又负责训练、验证、保存权重，还要记录最佳结果。大致可以看成：

```text
train_model()
│
├── 准备训练所需对象
├── 检查三个尺度的输出尺寸
├── 循环训练
│   └── tqdm 显示 batch 训练进度和 Loss
├── 验证模型
└── 保存 last.pt / best.pt
```

这样的写法在前面几章完全没有问题，因为我们的目标是先把训练流程跑通。但随着后面继续加入学习率调度、AMP、EMA、真实 OBB Loss、Validator 等功能，`train_model()` 会越来越长。所以这一次不只是把它简单搬到 `trainer.py`文件里，而是做一次真正的重构，我们把 `train_model()` 方法拆解包装成一个类，把原来的一个“大方法”，按照以下思路，拆成一个职责更加清楚的训练器。

```
train_model()

        ↓ 拆分职责

因此重构后的 `SimpleTrainer` 对应变成：
SimpleTrainer
├── __init__()             保存训练需要的对象
├── check_model_shapes()   检查多尺度输出
├── train_one_epoch()      训练一个 epoch
├── validate()             验证模型
├── save_model()           保存权重
└── train()                组织完整训练流程
```

训练流程没有改变，只是把原来的一个大方法拆成了几个职责明确的小方法。大方向明确以后，我们就一步一步完成这个重构。

#### 1. 定义类的成员变量

第 3 卷的 `train_model()` 中，`model`、`DataLoader`、`device`、`Loss`、`Optimizer` 等对象会在训练和验证过程中反复使用。因此将它们定义为 `SimpleTrainer` 类的成员变量：

```python
class SimpleTrainer:
    def __init__(self, model, train_loader, val_loader, device, lr=1e-3, save_dir="runs/weights"):
        self.model = model.to(device)                  # 模型
        self.train_loader = train_loader               # 训练集
        self.val_loader = val_loader                   # 验证集
        self.device = device                           # 计算设备
        self.save_dir = save_dir                       # 权重保存目录

        os.makedirs(save_dir, exist_ok=True)           # 创建保存目录

        self.criterion = nn.MSELoss()                  # Loss
        self.optimizer = optim.Adam(self.model.parameters(), lr=lr)  # Optimizer

        self.best_val_loss = float("inf")              # 当前最优验证 Loss
        self.epoch = 0                                 # 当前 epoch
        self.num_epochs = 0                            # 总 epoch 数
```

原来 `train_model()` 中的局部变量，现在变成了 `self.model`、`self.optimizer`、`self.train_loader `等成员变量，类中的其他方法可以直接使用。

#### 2. 把尺寸验算拆成 `check_model_shapes()`

第3卷在正式训练前会先构造一个虚拟输入，检查 P3、P4、P5 的输出尺寸。这一功能继续保留，输入代码的时候务必注意缩进：

```
def check_model_shapes(self, img_size=256):
    dummy = torch.randn(1, 3, img_size, img_size, device=self.device)
    self.model.eval()
    with torch.no_grad():
        outputs = self.model(dummy)
    print("各尺度输出形状:")
    for i, out in enumerate(outputs, start=3):
        stride = img_size // out.shape[-1]
        print(f"  P{i}: {list(out.shape)}  (stride={stride})")
    print("-" * 60)
```

这样 Trainer 在真正开始训练之前，仍然会先确认三个检测尺度是否正确。

#### 3. 把一个 epoch 的训练拆成 train_one_epoch()

原来的 `train_model()` 中，最核心的是这一段：

```python
pbar = tqdm(train_loader, desc=f"Epoch {epoch + 1}/{num_epochs}", leave=False)
for images, targets in pbar:
    ……
    ……
    loss.backward()
    optimizer.step()
```

这段代码完成了**把整个训练集跑一遍，也就是训练一个 epoch**的任务，也是训练的核心，现在把它抽出来。

重构以后，这部分完整放进 train_one_epoch()方法：

```python
def train_one_epoch(self):
    self.model.train()
    train_total_loss = 0.0

    pbar = tqdm(self.train_loader,
        desc=f"Epoch {self.epoch + 1}/{self.num_epochs}",
        leave=False
    )

    for images, targets in pbar:
        images = images.to(self.device)
        targets = [t.to(self.device) for t in targets]

        self.optimizer.zero_grad()

        outputs = self.model(images)
        loss = sum(self.criterion(out, target) for out, target in zip(outputs, targets))

        loss.backward()
        self.optimizer.step()

        train_total_loss += loss.item()

        pbar.set_postfix(loss=f"{loss.item():.4f}")

    return train_total_loss / len(self.train_loader)
```

注意，这里训练算法本身几乎没有变化。只是把原来`train_model()` 中的变量，换成了SimpleTrainer类的成员变量。


#### 4. 把 `evaluate()` 搬进 Trainer

第3卷原来有一个独立的 `evaluate(……)`方法，现在 `evaluate(……)`方法中涉及的对象都已经成为 SimpleTrainer类的成员变量，因此可以直接变成：

```python
@torch.no_grad()
def validate(self):
    self.model.eval()
    total_loss = 0.0

    for images, targets in self.val_loader:
        images = images.to(self.device)
        targets = [t.to(self.device) for t in targets]

        outputs = self.model(images)
        loss = sum(self.criterion(out, target) for out, target in zip(outputs, targets))

        total_loss += loss.item()

    return total_loss / len(self.val_loader)
```

功能和原来的 evaluate() 相同，只是不再需要传入一大串参数。

#### 5. 把权重保存拆分为save_model方法

原来保存训练结果的代码：

```
torch.save(model.state_dict(), os.path.join(save_dir, "last.pt"))
```

统一封装为save_model(……)方法：

```
def save_model(self, filename):
    path = os.path.join(self.save_dir, filename)
    torch.save(self.model.state_dict(), path)
```

以后无论是保存本轮训练的结果还是最优结果，只需要：

```
self.save_model("last.pt")
```

或者：

```
self.save_model("best.pt")
```

#### 6. 用 train() 串起整个训练流程

前面的具体工作都拆出去以后，train()方法现在只需要负责组织训练流程：
```python
def train(self, num_epochs=20, img_size=256):
    self.num_epochs = num_epochs

    # 训练前先检查三个尺度的输出
    self.check_model_shapes(img_size)

    # 正式训练
    for epoch in range(num_epochs):
        self.epoch = epoch

        train_avg_loss = self.train_one_epoch()
        val_avg_loss = self.validate()

        print(
            f"Epoch [{epoch + 1:2d}/{num_epochs}] "
            f"| Train Loss: {train_avg_loss:.4f} "
            f"| Val Loss: {val_avg_loss:.4f}"
        )

        self.save_model("last.pt")

        if val_avg_loss < self.best_val_loss:
            self.best_val_loss = val_avg_loss
            self.save_model("best.pt")

            print(f"  --> 保存当前最佳模型，Val Loss = {self.best_val_loss:.4f}")
```

现在整个训练过程就非常清楚了：

```text
检查模型输出尺寸
       ↓
训练一个 epoch
       ↓
     验证
       ↓
保存 last.pt
       ↓
如果更优，保存 best.pt
       ↓
进入下一个 epoch
```

#### 7. 完整的 trainer.py

为了方便大家看到整个SimpleTrainer类的全貌，最后还是完整的把SimpleTrainer的代码贴一下，大家可以自行对照：

```python
"""
训练器
对标：ultralytics/engine/trainer.py 中的 BaseTrainer
"""

import os
import torch
import torch.nn as nn
import torch.optim as optim
from tqdm import tqdm


class SimpleTrainer:
    """管理模型训练、验证和权重保存。"""

    def __init__(self, model, train_loader, val_loader, device, lr=1e-3, save_dir="weights"):
        self.model = model.to(device)                  # 模型
        self.train_loader = train_loader               # 训练集
        self.val_loader = val_loader                   # 验证集
        self.device = device                           # 计算设备
        self.save_dir = save_dir                       # 权重保存目录

        os.makedirs(save_dir, exist_ok=True)           # 创建权重目录

        self.criterion = nn.MSELoss()                  # 损失函数
        self.optimizer = optim.Adam(self.model.parameters(), lr=lr)  # 优化器

        self.best_val_loss = float("inf")              # 当前最优验证 Loss
        self.epoch = 0                                 # 当前 epoch
        self.num_epochs = 0                            # 总 epoch 数

    def check_model_shapes(self, img_size=256):
        """训练前检查三个尺度的输出尺寸。"""

        dummy = torch.randn(1, 3, img_size, img_size, device=self.device)

        self.model.eval()

        with torch.no_grad():
            outputs = self.model(dummy)

        print("各尺度输出形状:")

        for i, out in enumerate(outputs, start=3):
            stride = img_size // out.shape[-1]
            print(f"  P{i}: {list(out.shape)}  (stride={stride})")

        print("-" * 60)

    def train_one_epoch(self):
        """训练一个 epoch。"""

        self.model.train()
        train_total_loss = 0.0

        pbar = tqdm(
            self.train_loader,
            desc=f"Epoch {self.epoch + 1}/{self.num_epochs}",
            leave=False
        )

        for images, targets in pbar:
            images = images.to(self.device)
            targets = [t.to(self.device) for t in targets]

            self.optimizer.zero_grad()

            outputs = self.model(images)
            loss = sum(self.criterion(out, target) for out, target in zip(outputs, targets))

            loss.backward()
            self.optimizer.step()

            train_total_loss += loss.item()

            pbar.set_postfix(loss=f"{loss.item():.4f}")

        return train_total_loss / len(self.train_loader)

    @torch.no_grad()
    def validate(self):
        """验证模型。"""

        self.model.eval()
        total_loss = 0.0

        for images, targets in self.val_loader:
            images = images.to(self.device)
            targets = [t.to(self.device) for t in targets]

            outputs = self.model(images)
            loss = sum(self.criterion(out, target) for out, target in zip(outputs, targets))

            total_loss += loss.item()

        return total_loss / len(self.val_loader)

    def save_model(self, filename):
        """保存模型权重。"""

        path = os.path.join(self.save_dir, filename)
        torch.save(self.model.state_dict(), path)

    def train(self, num_epochs=20, img_size=256):
        """完整训练流程。"""

        self.num_epochs = num_epochs

        # 训练前先检查输出尺寸
        self.check_model_shapes(img_size)

        # 正式训练
        for epoch in range(num_epochs):
            self.epoch = epoch

            train_avg_loss = self.train_one_epoch()
            val_avg_loss = self.validate()

            print(
                f"Epoch [{epoch + 1:2d}/{num_epochs}] "
                f"| Train Loss: {train_avg_loss:.4f} "
                f"| Val Loss: {val_avg_loss:.4f}"
            )

            self.save_model("last.pt")

            if val_avg_loss < self.best_val_loss:
                self.best_val_loss = val_avg_loss
                self.save_model("best.pt")

                print(f"  --> 保存当前最佳模型，Val Loss = {self.best_val_loss:.4f}")

```

> 炼器笔记：为什么Trainer不用继承nn.Module？
>
>因为Trainer不是神经网络——它不参与前向传播，不需要被 torch.save 保存参数。它是一个控制器，负责编排"模型-数据-优化器"三者的协作。在设计模式中，这叫Mediator（中介者）模式。

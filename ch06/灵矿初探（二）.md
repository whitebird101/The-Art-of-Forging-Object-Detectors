# 灵矿初探（二）

## 6.3 炼器灵矿：`DOTADataset`

有了正向和反向转换函数，我们就拥有了基础的 OBB 坐标工具，下一步，就可以创建真正的 Dataset了。我们需要解决的问题是：**一张磁盘上的图片和一份 DOTA8 标签，怎样一步一步变成模型能够处理的 Tensor 和旋转框**。

第 1 卷已经介绍过 PyTorch `Dataset` 最基本的两个接口：`__len__()` 和 `__getitem__(idx)`，这里不再重复它们的作用。

虽然知道创建 `Dataset` 要实现这两个接口，但是在具体实现时，作为一个初学者通常还是会发懵，到底要写什么代码？

如果你感到无从下手，主要原因大概还是对拥有的“法器”不熟悉。比如 `numpy` 库中的 `asarray` 方法，可以将一张图片转换成一个 `NumPy 数组`，而 `torch`库中的 `from_numpy`方法，可以进一步把 `NumPy 数组`转换成一个张量（Tensor），而旋转框部分则可以直接使用上一节刚刚完成的 `xyxyxyxy2xywhr()`。

有了核心“法器“，再把数据处理思路想清楚，自然就有了代码，至少是第一版的代码。

我们暂时采用最简单的数据处理流程，大致过程是这样的：

```text
扫描指定目录，获得图像和标签文件地址
          ↓
    __getitem__(idx)
          ↓
       读取图片
          ↓
 Resize → Tensor → 归一化
          ↓
  从标签文件读取四角点
          ↓
  xyxyxyxy → xywhr
          ↓
(image_tensor, labels, path)
```

Dataset 主要完成两件事：一边把图片整理成模型能够接受的 Tensor，另一边把原始四角点标签转换成后续模型需要的格式。

### 6.3.1 建立数据集对象

将 `dataset.py` 文件中的代码全部删除，MultiscaleFakeDataset类已经完成历史使命了。

在 `dataset.py`中重新录入以下代码：

```python
# Path库，用来处理文件和文件夹路径。 相比直接使用字符串拼接路径，Path 写法更加清晰，也能较好地兼容 Windows、Linux 等不同操作系统。
# NumPy库，主要用于数组和数值计算。
# PyTorch核心库，后续需要把图片和标签转换成 Tensor。
# PIL 中的 Image 用于读取图片。

from pathlib import Path
import numpy as np
import torch
from PIL import Image
from torch.utils.data import Dataset, DataLoader

# 导入前面在 ops.py 中实现的旋转框转换函数。
from ops import xyxyxyxy2xywhr


class DOTADataset(Dataset):
    """
    用于数据链路验证的简化 DOTA8 Dataset。
    """

    def __init__(self, img_dir, label_dir, img_size=640, class_names=None):
        """
        初始化数据集。
        参数:
        img_dir:图片所在文件夹。
        label_dir:标签文件所在文件夹。
        img_size:后续统一使用的图片尺寸，默认 640。
        class_names:类别名称列表。如果没有传入，则默认使用空列表。
        """
        
        # 将传入的目录转换成 Path 对象。
        self.img_dir = Path(img_dir) 
        self.label_dir = Path(label_dir)
        
        self.img_size = img_size  # 保存后续图片统一缩放到的尺寸。
        self.class_names = class_names or [] # 保存类别名称。

        # 扫描图片目录中的所有文件，sorted() 会对图片路径进行排序。
        # 每次运行程序时，数据集中文件的基本顺序保持稳定。
        self.img_files = sorted(
            f for f in self.img_dir.iterdir()
            if f.suffix.lower() in {".jpg", ".jpeg", ".png", ".bmp"}
        )

        # 如果一张图片都没有找到，说明图片路径可能配置错误，输出提示信息
        if not self.img_files:
            raise RuntimeError(
                f"在 {self.img_dir} 中没有找到图片"
            )

        # 输出数据集加载结果，方便检查       
        print(
            f"加载 {len(self.img_files)} 张图片，"
            f"目录：{self.img_dir}"
        )

    def __len__(self):
        """
        返回数据集中的样本数量。
        图片文件的数量就是 Dataset 的长度。
        """
        return len(self.img_files)
```

这一部分只是记录图片目录、标签目录和图片尺寸，并扫描出全部图片文件。真正的数据处理发生在 `__getitem__()` 中。

---

### 6.3.2 从图片到 Tensor

继续在 `DOTADataset` 中加入：

```python
    def __getitem__(self, idx):
        img_path = self.img_files[idx]

        # 1. 读取图片并统一为 RGB
        img = Image.open(str(img_path)).convert("RGB")

        # 2. 暂时直接缩放到固定正方形
        img = img.resize((self.img_size, self.img_size))

        # 3. HWC -> CHW，同时把像素值从 [0,255] 归一化到 [0,1]
        img_np = np.asarray(img, dtype=np.float32).transpose(2, 0, 1) / 255.0
        img_tensor = torch.from_numpy(img_np)

        # 4. 根据图片文件名寻找同名标签
        label_path = self.label_dir / f"{img_path.stem}.txt" #根据规则构造标签文件地址
        labels = self._load_label(label_path) #读取并处理标签数据，后面马上实现

        return img_tensor, labels, str(img_path)
```

一张普通 RGB 图片的数据排列通常是`[H, W, C]`，也就是 `高度 × 宽度 × 通道`，而 PyTorch 的 `Conv2d` 习惯使用 `[C, H, W]`，所以需要通过 `.transpose(2, 0, 1)`方法把通道维移到最前面。

图片中的原始像素值通常位于 `[0,255]` 区间，除以 `255.0` 后，原始像素就变成 `[0,1]` 区间的 `float32` 数据。因此，一张图片经历如下处理过程：

```text
PIL Image
    ↓ Resize
640 × 640
    ↓ HWC → CHW
3 × 640 × 640
    ↓ / 255
float32，范围 [0,1]
```

最终得到一个形状为`[3, 640, 640]`的张量 `img_tensor`，这就是神经网络可以直接接受的单张图像格式。

我们现在暂时采用最简单的 Resize，直接把一张图片拉伸成 `640×640` 的正方形，虽然这会改变原始宽高比例，但目前我们的核心是跑通，所以这么做并没有太多影。当然，正式训练时通常不会这么简单处理，而会使用 LetterBox 等方法，在尽量保持原始比例的同时补边，并同步变换标签，这个部分我们后续再说。

---

### 6.3.3 标签到 `xywhr`

在 `__getitem__`中我们使用了 `_load_label`函数来实现标签数据的读取和处理，我们现在来实现这个函数，继续录入以下代码：

```python
    def _load_label(self, label_path):
        classes = []
        corners = []

        if label_path.exists():
            with open(label_path, "r", encoding="utf-8") as f:
                for line in f:
                    parts = line.strip().split()

                    if len(parts) != 9:
                        continue

                    cls_id = int(parts[0])
                    coords = [float(v) for v in parts[1:]]
                    points = np.asarray(coords, dtype=np.float32).reshape(4, 2)

                    classes.append(cls_id)
                    corners.append(points)

        # 没有目标时，也返回结构一致的数据
        if not classes:
            return {
                "cls": torch.zeros(0, dtype=torch.long),
                "corners": np.zeros((0, 4, 2), dtype=np.float32),
                "bboxes": torch.zeros((0, 5), dtype=torch.float32),
            }

        cls = torch.tensor(classes, dtype=torch.long)
        cors = np.asarray(corners, dtype=np.float32)

        # DOTA8 标签中的四角点使用 [0,1] 归一化坐标。
        # 图片已经缩放为 img_size × img_size，因此恢复成当前图像上的像素坐标。
        cors_pixel = cors.copy()
        cors_pixel[:, :, 0] *= self.img_size
        cors_pixel[:, :, 1] *= self.img_size

        rboxes = xyxyxyxy2xywhr(cors_pixel)

        return {
            "cls": cls,
            "corners": cors,
            "bboxes": torch.from_numpy(rboxes),
        }
```

DOTA8 每一行标签由类别编号和 4 个顶点组成，也就是 `class x1 y1 x2 y2 x3 y3 x4 y4`，读取以后，8 个坐标被整理成 `(4, 2)` 的四角点形式，也就是4个 `(x, y)` 形式的顶点坐标。

这里标签中的坐标原本已经归一化到 `[0,1]`，但是有一个点需要注意，刚刚图片经过 Resize 后统一变成 `img_size × img_size` 大小。因此要对标注文件中的顶点坐标进行处理，确保标注框在 Resize 后的图像上也是正确的。处理方法也很简单：只需要让所有 `x` 乘以当前图像宽度、所有 `y` 乘以当前图像高度，就能重新得到正确的像素坐标。

由于当前宽高都是 `img_size`，所以代码写成：

```python
segs_pixel[:, :, 0] *= self.img_size
segs_pixel[:, :, 1] *= self.img_size
```

接下来调用上一节刚刚完成的转换函数 `xyxyxyxy2xywhr`，把四角点转换成规范化的 `xywhr`。

最终，一份标签同时保留三类信息：

```text
labels["cls"]       → 目标类别
labels["cors"]      → 原始归一化四角点
labels["bboxes"]    → 当前图像像素坐标下的 xywhr
```

转换完以后为什么还会保留 `corners` 这个四角点坐标呢？

因为两种表示各有用途。后续模型训练更关心 `xywhr`，而原始四角点非常适合检查标签、做几何变换和可视化，同时保留两种表示反而更加方便后续使用。

### 6.3.4 堆叠：`collate_fn`

现在单张图片已经能够正常读取，但当 DataLoader 把多张图片组成一个 Batch 时，还会遇到一个问题。

假设一个 Batch 中有 3 张图片（batchsize=3），分别包含 3、8、0 个目标。

由于图片经过 Resize 后尺寸完全相同，因此可以通过 `torch.stack(images)` 沿 Batch 维进行堆叠，得到形状为 `[B, 3, img_size, img_size]` 的 Tensor。目前 `img_size=640` ，所以就是 `[B, 3, 640, 640]`。

但标签不同。三张图片中的目标数量并不一样：

```text
图片 1，3个目标：bboxes.shape = [3, 5]
图片 2，8个目标：bboxes.shape = [8, 5]
图片 3，0个目标：bboxes.shape = [0, 5]
```

这里每个旋转框包含 `[cx, cy, w, h, r]` 5 个参数，但不同图片的目标数量不同，因此这些标签不能直接使用 `torch.stack()` 堆叠成规则 Tensor。

因此我们自己定义 `collate_fn` 方法：

```python
def collate_fn(batch):
    images, targets, paths = zip(*batch)
    images = torch.stack(images, dim=0)
    return images, list(targets), list(paths)
```

这里的策略非常简单：**图片尺寸统一，可以堆成 Tensor；每张图片的目标数量不同，不好直接堆叠，那就先不堆叠，标签就暂时保留成长度为 `B` 的列表。**

这里 `zip(*batch)`可以简单理解成：**把原来“按样本组织”的数据，重新整理成“按图片、标签和路径分别组织”。**

比如，根据前面实现的 `__getitem__()` 代码，一个包含 3 个样本的 `batch` 大致长这样：

```text
[
    (image_0, target_0, path_0),
    (image_1, target_1, path_1),
    (image_2, target_2, path_2)
]
```

`*batch` 相当于把这 3 个样本拆开交给 `zip()`函数，而 `zip()` 会按照相同位置重新组合，于是得到：

```
images  = (image_0, image_1, image_2)
targets = (target_0, target_1, target_2)
paths   = (path_0, path_1, path_2)
```

接下来，图片尺寸完全相同，可以直接 `images = torch.stack(images, dim=0)` 得到 `images.shape = [B, 3, 640, 640]`。

而标签数量不同，就暂时保留成长度为 `B` 的列表 `targets = [target_0, target_1, ..., target_B-1]`，其中每个 `target_i` 都是第 `i` 个样本对应的标签字典，保存第 `i` 张图片对应的类别、四角点和旋转框信息。

`path_i` 则是这张图片的文件路径。

所以，一个 Batch 最终大致长这样：

```text
images   → [B, 3, 640, 640]

targets  → [target_0, target_1, ..., target_B-1]

paths    → [path_0, path_1, ..., path_B-1]
```

接下来创建 DataLoader：

```python
def build_dataloader(dataset, batch_size=4, shuffle=True):
    return DataLoader(
        dataset,
        batch_size=batch_size,
        shuffle=shuffle,
        collate_fn=collate_fn,
        num_workers=0,
        drop_last=False,
    )
```

这里暂时把 `num_workers` 设为 `0`，在Windows 环境中可以减少多进程 DataLoader 带来的额外问题。


### 6.3.5 从 YAML 创建真正的 DOTA8 DataLoader

到这里我们已经拥有了 `DOTADataset` 和通用的 `build_dataloader()`，但还缺最后一步：**根据 `dota8.yaml` 中的配置，把路径、类别、Dataset 和 DataLoader 真正组装起来。**

这部分代码目前仍然放在 `dataset.py` 中。

在 `dataset.py` 中补充 `yaml` 和下载函数 `download_dota8` 的导入：

```python
import yaml

```

然后在 `dataset.py` 最后加入：

```python
def build_dota8_loader(batch_size=2):
    # 读取 DOTA8 配置
    with open("cfg/dota8.yaml", "r", encoding="utf-8") as f:
        cfg = yaml.safe_load(f)

    # 按 YAML 指定的位置准备数据
    data_dir = download_dota8(cfg["path"])
    if data_dir is None:
        raise RuntimeError(
            "DOTA8 下载失败，请检查网络或数据目录。"
        )

    base = Path(data_dir)
    train_dir = Path(cfg["train"])

    # DOTA8 中类别按 class_id 顺序定义
    class_names = list(cfg["names"].values())

    dataset = DOTADataset(
        img_dir=base / train_dir,
        label_dir=base / "labels" / train_dir.name,
        img_size=640,
        class_names=class_names,
    )

    # 当前主要用于检查数据，暂时不打乱顺序
    loader = build_dataloader(
        dataset,
        batch_size=batch_size,
        shuffle=False,
    )

    return loader, dataset, class_names
```
这里 `build_dota8_loader` 函数的除了 `loader` 和 `class_names`，还把 `dataset` 也一并返回出来了，这是以备后续需要值对构建的 `dataset` 进行操作。

这样，`dataset.py` 的职责就完整了：`DOTADataset` 负责单个样本，`collate_fn` 负责组织 Batch，`build_dataloader()` 负责创建通用 DataLoader，而 `build_dota8_loader()` 则进一步读取 `dota8.yaml`，把 DOTA8 的具体路径和类别配置接入进来。

这里也让 `dota8.yaml` 真正成为数据配置的唯一来源。以后如果数据目录从 `dota8` 改成其他位置，只需要修改 YAML，不需要再去改 Python 代码。

## 6.4 最简单直接的确认：看一眼标注框

到这里，Dataset 已经能够返回真实图片和标签。

但数据能够正常读取，并不代表标签一定正确。坐标恢复错误、角度方向错误、宽高交换后角度没有同步处理等问题，都可能不会触发任何程序异常，但是却可能存在数据错误。

所以真正把数据送入模型之前，先做一次最直接的检查：**把旋转框重新画回图片，看一眼它是否还落在正确的位置。**

为了核查数据梳理流程中是否存在错误，我们不直接使用标注中的四角点来绘制，而是走一遍：

```text
原始四角点
    ↓
xyxyxyxy2xywhr()
    ↓
xywhr
    ↓
xywhr2xyxyxyxy()
    ↓
重新得到四角点
    ↓
画回图片
```

这样做是为了检查刚刚实现的两套坐标转换函数能否在几何上闭环。另外，当前 Dataset 已经把图片 Resize 到 `img_size × img_size`，`bboxes` 也已经转换成这一尺寸下的像素坐标，所以我们需要把旋转框画在 **Resize 后、真正准备送入模型的图片** 上。

这样检查的才是模型实际看到的图像和标签是否正确。

在根目录下新建 `visualize.py`文件，录入以下代码：

```python
from pathlib import Path
import random
import matplotlib.pyplot as plt
from matplotlib.patches import Polygon
from ops import xyxyxyxy2xywhr, xywhr2xyxyxyxy

def draw_boxes(ax, corners):
    """
    绘制旋转框四角点。
    corners:shape=(N,4,2)
    """
    for box in corners:
        #根据传入的顶点，构建线宽1、红色多边形（矩形），也就是标注框啦
        polygon = Polygon(
            box,
            closed=True,
            fill=False,
            edgecolor="red",
            linewidth=1,
            zorder=10,
        )

        ax.add_patch(polygon)


def visualize_obb_conversion(image, corners, save_path):
    """
    对比验证：原始四角点 vs 四角点 -> xywhr -> 四角点

    参数:
    image:RGB图片，HWC格式
    corners:原始旋转框四角点，shape=(N,4,2)
    save_path:保存路径
    """
    
    # 将归一化坐标转换为当前图片像素坐标
    corners_pixel = corners.copy()

    h, w = image.shape[:2]

    corners_pixel[:, :, 0] *= w
    corners_pixel[:, :, 1] *= h

    # 四角点转换为 xywhr
    rboxes = xyxyxyxy2xywhr(corners_pixel)

    # xywhr恢复为四角点
    recovered_corners = xywhr2xyxyxyxy(rboxes)

    fig, axes = plt.subplots(1,2,figsize=(12, 6))

    # 左图：原始标注
    axes[0].imshow(image)
    axes[0].set_title("Original corners")
    axes[0].axis("off")

    draw_boxes(axes[0], corners_pixel)

    # 右图：转换恢复结果
    axes[1].imshow(image)
    axes[1].set_title("corners → xywhr → corners" )
    axes[1].axis("off")

    draw_boxes(axes[1], recovered_corners)

    plt.tight_layout()

    save_path = Path(save_path)
    save_path.parent.mkdir(parents=True, exist_ok=True)

    plt.savefig(save_path, dpi=150, bbox_inches="tight")
    plt.close(fig)


def visualize_dataset_samples(dataset, num_samples=4, save_dir="runs/visualize", seed=42):
    """
    随机选择数据集图片进行 OBB 转换检查。

    参数:
    dataset:DOTADataset对象
    num_samples:检查图片数量，默认4张，在数据集中随机选择
    save_dir:输出目录
    seed:随机种子，保证结果可复现
    """

    save_dir = Path(save_dir)
    save_dir.mkdir(parents=True, exist_ok=True)
    total = len(dataset)

    # 图片数量不足时全部检查
    if total <= num_samples:
        indices = list(range(total))

    else:
        random.seed(seed)
        indices = random.sample(range(total), num_samples)

    print( f"随机选择 {len(indices)} 张图片进行可视化检查:")

    for idx in indices:

        # Dataset返回：
        # image tensor, 标签信息, 图片路径
        img_tensor, labels, path = dataset[idx]

        # Tensor CHW -> HWC
        image = (img_tensor.permute(1, 2, 0).numpy())

        # 原始四角点
        corners = labels["corners"]

        if len(corners) == 0:
            print(f"{path} 无目标，跳过")
            continue

        save_path = (save_dir /f"{Path(path).stem}_compare.png")
        visualize_obb_conversion(image, corners, save_path)
        print(f"保存完成: {save_path}")
```

如果绘制结果中，旋转框位置基本正确、方向没有明显错误、没有出现整体偏移或 `90°` 错位，就可以认为当前 OBB 标签处理基本可靠。

对于 OBB 来说，可视化尤其重要。因为角度是否正确，单看一串 `0.42`、`1.17` 这样的弧度数字几乎没有直觉；画出来，一眼就能看出问题。

`visualize_dataset_samples`函数，我们稍后会在main.py中调用。

## 6.5 灵矿入炉：真实 DOTA8 第一次流入模型

现在两条线路已经准备好了：`dataset.py` 负责从 `dota8.yaml` 创建真实 DataLoader，`model.py` 则继续使用第 5 卷已经完成的 `DetectionModel`，根据 `yolo-obb-mini.yaml` 动态构建网络。

前面几卷我们使用 `torch.randn()` 构建虚拟数据来验证模型，它能够证明网络结构可以正常执行，但随机张量毕竟不是真实图片。从这一节开始，模型输入正式换成 DOTA8。

但是这里有个问题需要特别注意：

> **不能简单把原来的 `MultiscaleFakeDataset` 直接替换成 `DOTADataset`后直接训练。**

这是因为，第5卷中的虚拟标签是按照 `SimpleHead` 的输出形式人为构造的，它与模型输出张量尺寸完全一致，因此可以直接计算MSELoss。而真实 DOTA8 标签表示的是实际目标，之前我们已经知道，真实目标的格式是 `类别 + 四角点 + xywhr`，它和当前 `SimpleHead` 的输出是不匹配的，像第5卷一样通过 `criterion(out, target) ` 计算MSELoss，程序就会报错。

因此本卷先验证真实数据读取和前向传播的功能。真正的训练要到第7卷才能实现。

在 `main.py` 文件中，新增一个 `main_dota8_forward`方法。

首先调整依赖，将 `from dataset import MultiscaleFakeDataset, build_dataloader` 删除，补充导入 `visualize_batch`、 `build_dota8_loader` 方法：

``` python
from visualize import visualize_batch
from dataset import build_dota8_loader
```

然后录入以下代码：

``` python
def main_dota8_forward():

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")

    # 加载真实 DOTA8 数据，batch_size设置为2
    loader,dataset, class_names = build_dota8_loader(batch_size=2)
    
    #绘制对比图，检查标注框经转换后是否正确
    visualize_dataset_samples(
        dataset,
        num_samples=4,
        save_dir="runs/visualize")

    images, targets, paths = next(iter(loader))
    
    print(f"输入图片: {list(images.shape)}")
    
    # 构建模型
    model = DetectionModel(
        "cfg/yolo-obb-mini.yaml",
        nc=len(class_names)).to(device)

    images = images.to(device)

    model.eval()

    with torch.no_grad():
        outputs = model(images)

    print("\n" + "=" * 60)
    print("真实 DOTA8 前向传播")
    print("=" * 60)
    print(f"输入图片: {list(images.shape)}")
    print(f"图片数量: {len(paths)}")

    # 查看各尺度输出
    if isinstance(outputs, (list, tuple)):
        for i, out in enumerate(outputs):
            print(f"输出 {i}: {list(out.shape)}")
    else:
        print(f"输出: {list(outputs.shape)}")
```

在构建模型时，现在使用 `nc=len(class_names)`，而不是再次写死 `nc=15`，这样类别数量直接来自 `dota8.yaml`。

运行入口部分改为调用 `main_dota8_forward` 函数：

``` python
if __name__ == "__main__":
    main_dota8_forward()
```

运行最新的代码，检查可视化之后的图像，看经过处理后，标注框的位置是否正确，是否仍然紧贴卫星图中的目标？

如果模型能够正常接收 `[B, 3, 640, 640]` 的真实图片，并在多个尺度上产生输出，空间尺寸符合 P3 / P4 / P5 预期，没有出现 shape 或 dtype 错误，这就说明真实数据已经第一次完整通过了我们自己搭建的网络。

## 3.5 重铸根基：用核心算子升级模型

前面几节，我们一直在**拆零件、看原理，手搓一个个核心算子。**

修炼到这里，作为一名初入门径的“炼器师”，我们的乾坤袋里已经攒下了几件真正的基础阵法。

在使用之前，不妨先把它们他们仔细检视一遍，因为这些将会是我们炼器之路上最基础也是最最重要的阵法：

-   `autopad`：自动计算卷积所需的 padding
-   `Conv`：由 Conv2d、BatchNorm2d 和 SiLU 组成的基础卷积模块
-   `Bottleneck`：加入残差连接的基础特征提炼模块
-   `C2f`：通过分支与特征融合增强信息流动
-   `C3k2`：在 C2f 基础上进一步升级的特征提取模块
-   `SPPF`：在保持特征图尺寸不变的情况下扩大感受野，汇聚更大范围的上下文信息

它们的依赖关系是：

```text
C3k2 → C2f → Bottleneck → Conv → autopad

SPPF ───────────────────→ Conv → autopad
```

箭头表示“上层模块会调用下层模块”。`Conv` 是整个算子体系的基础，`C3k2` 和 `SPPF` 则是在它之上搭起来的更高层结构。

请确保你的main.py文件中有这些类和方法，并且所有的代码都是正确的。

之前我们为了测试梯度消失的两个方法 `gradient_experiment` 和 `gradient_experiment_yolo_conv`，此时已经可以删除了，当然，保留也可以。


**接下来，该把这些“阵法”真正装回模型了。**

### 3.5.1 脱胎换骨：这次到底升级了什么

先回忆一下第 2 卷的模型。当时我们的目标只有一个：

> **先把 Backbone、FPN、多尺度输出和反向传播完整跑通。**

所以很多结构都做得非常简单。

现在经过第3卷，我们已经知道工业级网络为什么不会只是简单地堆 `Conv2d + ReLU`，也已经亲手实现了更完整的基础模块。因此，这一次升级可以概括成下面几项：

| 位置 | 第 2 卷 | 第 3 卷升级后 |
| --- | --- | --- |
| 基础卷积 | `nn.Conv2d + ReLU` | `Conv = Conv2d + BN + SiLU` |
| 特征提取 | 简单卷积堆叠 | `C3k2` |
| 残差与分流 | 基本没有 | Bottleneck + C2f/CSP 分流 |
| 深层上下文 | 没有专门模块 | `SPPF` |
| FPN 融合 | 简单 Conv | 使用 `C3k2` 继续加工融合后的特征 |
| 检测头 | 简化 Head | 暂时保持不变 |
| Loss |  MSE | 暂时保持不变 |

注意最后两项。本卷我们仍然**不碰 OBB Head 和 OBB Loss**。

### 3.5.2 按图施工：新版 YOLOLikeDetector

先不要急着写代码，我们先把整个模型的处理流程画出来，把思路理清楚。

输入仍然使用一张 `256×256` 的 RGB 图片：

```text
输入图像
[B, 3, 256, 256]
        │
        ▼
Conv, s=2
[B, 16, 128, 128]
        │
        ▼
Conv, s=2
[B, 32, 64, 64]
        │
        ▼
C3k2
[B, 32, 64, 64]
        │
        ▼
Conv, s=2
[B, 64, 32, 32]
        │
        ▼
C3k2
        ├──────────────→ P3  [B, 64, 32, 32]   stride=8
        ▼
Conv, s=2
[B, 128, 16, 16]
        │
        ▼
C3k2
        ├──────────────→ P4  [B, 128, 16, 16]  stride=16
        ▼
Conv, s=2
[B, 128, 8, 8]
        │
        ▼
C3k2
        │
        ▼
SPPF
        └──────────────→ P5  [B, 128, 8, 8]    stride=32
```

到这里，Backbone 产生了我们熟悉的三层特征：

```text
P3：32×32   —— 分辨率最高，保留更多空间细节
P4：16×16   —— 中间尺度
P5： 8×8    —— 分辨率最低，语义更深、上下文范围更大
```

接下来沿用第 2 卷的 FPN 思路，从深层往浅层逐级融合：

```text
P5 [128, 8, 8]
      │
      ▼
1×1 Conv：128 → 64
      │
      ▼
Upsample ×2
      ├──────────────────────┐                    │
      ▼                      ▼
[64,16,16]              P4 [128,16,16]
      └──────────┬───────────┘
                 ▼
          Concat：64+128=192
                 │
                 ▼
          C3k2：192 → 64
                 └────────────→ F4 [64,16,16]


F4 [64,16,16]
      │
      ▼
1×1 Conv：64 → 32
      │
      ▼
Upsample ×2
      ├─────────────────────┐
      ▼                     ▼
[32,32,32]              P3 [64,32,32]
      └──────────┬──────────┘
                 ▼
          Concat：32+64=96
                 │
                 ▼
           C3k2：96 → 32
                 └────────────→ F3 [32,32,32]
```

最后，把 `F3、F4、P5` 分别送进三个临时预测头：

```text
F3 ──→ Head3 ──→ [B, C, 32, 32]
F4 ──→ Head4 ──→ [B, C, 16, 16]
P5 ──→ Head5 ──→ [B, C,  8,  8]
```

其中：

```python
C = num_classes + 8
```

这里的 `8` 仍然是我们从第 2 卷沿用下来的**回归占位通道**，现在这三个 Head 还只是普通的 `1×1 Conv`，输出的也是原始张量，目的是让训练代码能够继续跑通。

#### 完整模型代码

现在再来看完整代码，结构就非常清楚了，请把以下代码输入main.py文件，注意，这里检测模型的类名已经是 `YOLOLikeDetector` 了。

代码行数比较多，输入的时候千万仔细，不要写错。更重要的是，请不要整个copy and  paste，请一定自己手动输入所有的代码：

```python
class YOLOLikeDetector(nn.Module):
    """使用第三卷核心算子搭建的教学版多尺度检测器。"""

    def __init__(self, num_classes=2):
        super().__init__()
        self.out_channels = num_classes + 8

        # ---------------- Backbone ----------------
        self.stem = Conv(3, 16, 3, 2)             # 256 -> 128
        self.down1 = Conv(16, 32, 3, 2)           # 128 -> 64
        self.stage1 = C3k2(32, 32, n=1)

        self.down2 = Conv(32, 64, 3, 2)           # 64 -> 32
        self.stage2 = C3k2(64, 64, n=1)           # P3, stride=8

        self.down3 = Conv(64, 128, 3, 2)          # 32 -> 16
        self.stage3 = C3k2(128, 128, n=1)         # P4, stride=16

        self.down4 = Conv(128, 128, 3, 2)         # 16 -> 8
        self.stage4 = C3k2(128, 128, n=1)
        self.sppf = SPPF(128, 128)                # P5, stride=32

        # ---------------- Neck：沿用第2卷 FPN ----------------
        self.up = nn.Upsample(scale_factor=2, mode="nearest")

        self.lateral5 = Conv(128, 64, 1, 1)
        self.fpn4 = C3k2(192, 64, n=1)            # 64 + 128 = 192

        self.lateral4 = Conv(64, 32, 1, 1)
        self.fpn3 = C3k2(96, 32, n=1)             # 32 + 64 = 96

        # ---------------- 临时预测头 ----------------
        self.head3 = nn.Conv2d(32, self.out_channels, 1)
        self.head4 = nn.Conv2d(64, self.out_channels, 1)
        self.head5 = nn.Conv2d(128, self.out_channels, 1)

    def forward(self, x):
        # Backbone
        x = self.stem(x)                          # [B, 16, 128, 128]
        x = self.down1(x)                         # [B, 32, 64, 64]
        x = self.stage1(x)                        # [B, 32, 64, 64]

        x = self.down2(x)                         # [B, 64, 32, 32]
        p3 = self.stage2(x)                       # [B, 64, 32, 32]

        x = self.down3(p3)                        # [B, 128, 16, 16]
        p4 = self.stage3(x)                       # [B, 128, 16, 16]

        x = self.down4(p4)                        # [B, 128, 8, 8]
        x = self.stage4(x)                        # [B, 128, 8, 8]
        p5 = self.sppf(x)                         # [B, 128, 8, 8]

        # FPN：P5 -> P4
        up5 = self.up(self.lateral5(p5))          # [B, 64, 16, 16]
        f4 = torch.cat([up5, p4], dim=1)          # [B, 192, 16, 16]
        f4 = self.fpn4(f4)                        # [B, 64, 16, 16]

        # FPN：F4 -> P3
        up4 = self.up(self.lateral4(f4))          # [B, 32, 32, 32]
        f3 = torch.cat([up4, p3], dim=1)          # [B, 96, 32, 32]
        f3 = self.fpn3(f3)                        # [B, 32, 32, 32]

        # 三尺度输出
        return [
            self.head3(f3),                       # [B, C, 32, 32]
            self.head4(f4),                       # [B, C, 16, 16]
            self.head5(p5),                       # [B, C, 8, 8]
        ]
```

这份代码真正值得关注的，不是“行数变多了”，而是模型内部已经开始出现清晰的职责分工：

```text
Conv
负责降采样、调整通道

C3k2
负责主要特征提取和融合

SPPF
负责在 Backbone 后段聚合不同范围的上下文

Upsample + Concat
负责跨层级传递和拼接特征

C3k2
继续加工拼接后的特征

Head
暂时负责把特征映射到需要的输出通道数
```

这已经比第 2 卷单纯“堆几个卷积”更接近现代目标检测网络（比如YOLO)的组织方式了。

#### Backbone 的尺寸变化

把 Backbone 再单独拿出来看一看：

| 层 | 操作 | 输入 | 输出 | 作用 |
| --- | --- | --- | --- | --- |
| `stem` | `Conv(3→16, s=2)` | `[B,3,256,256]` | `[B,16,128,128]` | 第一次降采样 |
| `down1` | `Conv(16→32, s=2)` | `[B,16,128,128]` | `[B,32,64,64]` | 第二次降采样 |
| `stage1` | `C3k2(32→32)` | `[B,32,64,64]` | `[B,32,64,64]` | 特征提取 |
| `down2` | `Conv(32→64, s=2)` | `[B,32,64,64]` | `[B,64,32,32]` | 得到 stride=8 |
| `stage2` | `C3k2(64→64)` | `[B,64,32,32]` | `[B,64,32,32]` | 形成 P3 特征源 |
| `down3` | `Conv(64→128, s=2)` | `[B,64,32,32]` | `[B,128,16,16]` | 得到 stride=16 |
| `stage3` | `C3k2(128→128)` | `[B,128,16,16]` | `[B,128,16,16]` | 形成 P4 特征源 |
| `down4` | `Conv(128→128, s=2)` | `[B,128,16,16]` | `[B,128,8,8]` | 得到 stride=32 |
| `stage4` | `C3k2(128→128)` | `[B,128,8,8]` | `[B,128,8,8]` | 深层特征提取 |
| `sppf` | `SPPF(128→128)` | `[B,128,8,8]` | `[B,128,8,8]` | 聚合多范围上下文，形成 P5 |

这里特别注意两点。

第一，`P3、P4、P5` 它们分别对应：

```text
P3：stride = 8
P4：stride = 16
P5：stride = 32
```

对于 `256×256` 输入，因此正好得到：

```text
256 / 8  = 32
256 / 16 = 16
256 / 32 = 8
```

第二，我们把 SPPF 放在模型 Backbone 的后段，此时特征图已经比较小、语义也比较深，在这里做多范围上下文聚合比较合适。

#### FPN 为什么会出现 192 和 96 通道？

第一次融合：

```text
P5：128 通道
 ↓ 1×1 Conv
64 通道
 ↓ Upsample
64 通道

P4：128 通道

Concat：64 + 128 = 192 通道
```

所以：

```python
self.fpn4 = C3k2(192, 64, n=1)
```

第二次融合也是一样：

```text
F4：64 通道
 ↓ 1×1 Conv
32 通道
 ↓ Upsample
32 通道

P3：64 通道

Concat：32 + 64 = 96 通道
```

所以：

```python
self.fpn3 = C3k2(96, 32, n=1)
```

这也是阅读网络代码时非常重要的一项基本功：

> **只要出现 Concat，就一定要顺手把各路通道数加一遍。**

很多“expected input to have xxx channels”的报错，就是从这里来的。

### 3.5.3 对账验收：检查 P3、P4、P5 的张量

模型写完以后，不要马上训练。随着模型越来越复杂，我们要先来快速验证一下模型的正确性。

> **先拿一张虚拟图片跑一遍，看看每一层的尺寸是不是我们预想的那样。**

这就是最便宜、也最有效的结构检查。

可以在 `main.py` 中加入：

def check_model_shapes():
    model = YOLOLikeDetector(num_classes=2)
    model.eval()

    x = torch.randn(1, 3, 256, 256)

    with torch.no_grad():
        outputs = model(x)

    print("各尺度输出形状：")

运行后，应该得到这样的尺寸：

```text
P3: [1, 10, 32, 32], stride=8
P4: [1, 10, 16, 16], stride=16
P5: [1, 10, 8, 8],   stride=32
```

如果这一步能跑通，至少说明三件事：

1. Backbone 的五次 `stride=2` 降采样是正确的；
2. FPN 中两次 Upsample + Concat 的空间尺寸和通道数能够对应上；
3. 三个 Head 都收到了预期尺度的特征图。

为什么通道数是 `10`？因为这里设置：

```text
num_classes = 2
回归占位通道 = 8

所以：
2 + 8 = 10
```

再次强调：这里的 `10` 只是当前人为规定的输出格式，用来验证三尺度网络和训练链路的。

到这里，我们验证了**模型结构在张量层面已经能够闭合。** 但“能前向”还不代表“能训练”。所以最后还要做一次点火试车。

### 3.5.4 点火试车：跑通完整训练闭环

这一节暂时不追求检测精度。

我们只验证新的 Backbone + FPN + Head 能不能顺利完成前向传播、计算 Loss、反向传播和参数更新。

因此数据集仍然沿用第 2 卷的 `MultiscaleFakeDataset`。

#### 1. 构造三尺度假数据

请在main.py文件中输入以下代码：

```python
class MultiscaleFakeDataset(Dataset):
    def __init__(self, num_samples=100, img_size=256, num_classes=2):
        super().__init__()
        self.images = []
        self.targets = []

        channels = num_classes + 8
        grid_sizes = [img_size // 8, img_size // 16, img_size // 32]

        for _ in range(num_samples):
            image = torch.randn(3, img_size, img_size)
            target_list = [torch.randn(channels, gs, gs) for gs in grid_sizes]

            self.images.append(image)
            self.targets.append(target_list)

    def __len__(self):
        return len(self.images)

    def __getitem__(self, idx):
        return self.images[idx], self.targets[idx]
```

对于 `256×256` 输入，它会为三个尺度分别生成：

```text
P3 target：[C, 32, 32]
P4 target：[C, 16, 16]
P5 target：[C,  8,  8]
```

这些 Target 都是随机数，没有真实目标含义。它们存在的目的只有一个，就是给三个输出头准备形状完全匹配的“虚拟答案”，让整个训练计算图能够跑起来。

#### 2. 组装 batch

因为一个样本里包含三个尺度的 Target，所以需要自定义 `collate_fn`，请在main.py中输入以下代码：

```python
def collate_fn(batch):
    images = torch.stack([item[0] for item in batch])
    targets = [torch.stack([item[1][s] for item in batch]) for s in range(3)]
    return images, targets
```

假设 `batch_size=4`，那么：

```text
images
[B, 3, 256, 256]

            ┌→ targets[0]：[B, C, 32, 32]
targets ────┼→ targets[1]：[B, C, 16, 16]
            └→ targets[2]：[B, C,  8,  8]
```

正好可以与模型的三个输出一一配对。

#### 3. 验证函数

这里仍然使用 `MSELoss`。不是因为目标检测应该使用 MSE，而是因为现在只需要一个简单、可导的 Loss 来检查反向传播，请在 `main.py` 文件中输入以下代码：

```python
@torch.no_grad()
def evaluate(model, loader, criterion, device):
    model.eval()
    total_loss = 0.0

    for images, targets in loader:
        images = images.to(device)
        targets = [t.to(device) for t in targets]

        outputs = model(images)
        loss = sum(criterion(out, target) for out, target in zip(outputs, targets))
        total_loss += loss.item()

    return total_loss / len(loader)
```

这里不再使用 `mock mAP`。因为 `1 / Loss` 和真正的 mAP 没有任何等价关系。既然这一阶段只是验证训练链路，就老老实实看 `Train Loss` 和 `Val Loss` 即可。

#### 4. 完整训练函数

```python
def train_model():
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    print(f"计算设备: {device}")

    img_size = 256
    num_classes = 2
    batch_size = 4
    num_epochs = 20
    save_dir = "weights"
    os.makedirs(save_dir, exist_ok=True)

    train_dataset = MultiscaleFakeDataset(80, img_size, num_classes)
    val_dataset = MultiscaleFakeDataset(20, img_size, num_classes)

    train_loader = DataLoader(train_dataset, batch_size=batch_size, shuffle=True, collate_fn=collate_fn)
    val_loader = DataLoader(val_dataset, batch_size=batch_size, shuffle=False, collate_fn=collate_fn)

    model = YOLOLikeDetector(num_classes=num_classes).to(device)
    criterion = nn.MSELoss()
    optimizer = optim.Adam(model.parameters(), lr=1e-3)

    best_val_loss = float("inf")

    # ---------- 训练前先做一次尺寸验算 ----------
    dummy = torch.randn(1, 3, img_size, img_size, device=device)

    model.eval()
    with torch.no_grad():
        outputs = model(dummy)

    print("各尺度输出形状:")
    for i, out in enumerate(outputs, start=3):
        stride = img_size // out.shape[-1]
        print(f"  P{i}: {list(out.shape)}  (stride={stride})")

    print("-" * 60)

    # ---------- 正式进入训练循环 ----------
    for epoch in range(num_epochs):
        model.train()
        train_total_loss = 0.0

        pbar = tqdm(train_loader, desc=f"Epoch {epoch + 1}/{num_epochs}", leave=False)

        for images, targets in pbar:
            images = images.to(device)
            targets = [t.to(device) for t in targets]

            optimizer.zero_grad()

            outputs = model(images)
            loss = sum(criterion(out, target) for out, target in zip(outputs, targets))

            loss.backward()
            optimizer.step()

            train_total_loss += loss.item()
            pbar.set_postfix(loss=f"{loss.item():.4f}")

        train_avg_loss = train_total_loss / len(train_loader)
        val_avg_loss = evaluate(model, val_loader, criterion, device)

        print(
            f"Epoch [{epoch + 1:2d}/{num_epochs}] "
            f"| Train Loss: {train_avg_loss:.4f} "
            f"| Val Loss: {val_avg_loss:.4f}"
        )

        torch.save(model.state_dict(), os.path.join(save_dir, "last.pt"))

        if val_avg_loss < best_val_loss:
            best_val_loss = val_avg_loss
            torch.save(model.state_dict(), os.path.join(save_dir, "best.pt"))
            print(f"  --> 保存当前最佳模型，Val Loss = {best_val_loss:.4f}")
```

这一阶段真正要观察的是：

1. 前向传播能否正常完成；
2. 三尺度输出是否与 Target 一一对应；
3. Loss 是否为正常有限值，没有出现 `NaN` 或 `Inf`；
4. `loss.backward()` 能否正常完成；
5. 优化器能否更新参数；
6. 模型权重能否正常保存。

如果这些都没有问题，就说明：

> **我们刚刚手搓出来的 Conv、C3k2 和 SPPF，已经不再是几个孤立的零件，而是真正进入了一条完整的训练计算图。**

这才是这一节最重要的验收标准。

#### 5、tqdm：给训练循环加上进度条

刚刚的训练代码里出现了一个新东西：

```
from tqdm import tqdm
```

`tqdm` 是一个非常常用的 Python 进度条库。它的作用很简单：**给循环，加上可以实时看到的进度条。**

比如原来的训练循环是：

```
for images, targets in train_loader:
    ...
```

我们把 `train_loader` 用 `tqdm()` 包起来：

```
pbar = tqdm(train_loader)

for images, targets in pbar:
    ...
```

训练时，就可以看到类似这样的进度信息：

```
Epoch 1/20:  65%|█████████████       | 13/20 [00:03<00:01]
```

也就是说，你可以很直观地看到：

-   当前训练到了多少个 batch；
-   总共有多少个 batch；
-   已经完成了多少百分比；
-   大概还需要多久。

在我们的代码里，写得稍微完整一些：

```
pbar = tqdm(
    train_loader,
    desc=f"Epoch {epoch + 1}/{num_epochs}",
    leave=False
)
```

其中 `desc=f"Epoch {epoch + 1}/{num_epochs}"` 表示在进度条前面显示当前 Epoch，例如：

```
Epoch 3/20
```

而 `leave=False` 表示这一轮 Epoch 训练完成之后，不把当前进度条一直留在屏幕上，避免训练很多轮之后终端里堆满进度条。

除了显示训练进度，我们通常还希望实时看到当前 `Loss` 的具体值。所以后面又加上了：

```
pbar.set_postfix(loss=f"{loss.item():.4f}")
```

`set_postfix()` 可以在进度条后面附加一些我们关心的信息。

例如：

```
Epoch 3/20:  70%|██████████████      | 14/20 [00:03<00:01, loss=0.4821]
```

这样训练过程中，就可以一边看进度，一边看当前 batch 的 Loss。

这就像在黑暗中修炼——你不知道灵力运转到了哪条经脉，也不知道还要多久才能突破。tqdm 就是那双让你随时洞察修炼进度的"法眼"。以后训练深度学习模型时，`tqdm` 会经常出现，是一个非常实用的小工具。

## 总结

第三卷走到这里，我们完成了一次非常重要的跨越。

第 2 卷解决的是**神经网络到底是怎样前向计算、怎样计算 Loss、又怎样通过反向传播更新参数的？**
第三卷继续向前追问**既然计算图已经能跑起来，工业级目标检测网络为什么要把内部零件设计成现在这个样子？**

围绕这个问题，我们一路完成了：

```text
普通 Conv2d + ReLU
        ↓
发现深层训练中的梯度传播问题
        ↓
Conv2d + BN + SiLU
        ↓
Bottleneck + 残差连接
        ↓
C2f：CSP 分流与多阶段特征复用
        ↓
C3k2：YOLO11 中的重要特征提取模块
        ↓
SPPF：多范围上下文聚合
        ↓
重新装回完整检测模型
```

###### 从第 2 卷到第 3 卷，我们完成了以下升级：

| 维度 | 第 2 卷 | 第 3 卷 |
| --- | --- | --- |
| 反向传播 | 理解梯度怎样沿计算图传播 | 开始关注深层网络中的梯度稳定性 |
| 基础卷积 | `Conv2d + ReLU` | `Conv2d + BN + SiLU` |
| 特征提取 | 简单 Conv 堆叠 | Bottleneck、C2f、C3k2 |
| 残差结构 | 只理解基本计算图 | 真正加入残差捷径 |
| CSP | 没有 | 学会分流、加工、再融合 |
| 上下文聚合 | 依赖卷积自然扩大范围 | 加入 SPPF 主动汇聚多范围上下文 |
| 多尺度融合 | FPN + 简单 Conv | FPN + C3k2 |
| 完整训练 | 简单教学网络 | 新核心算子进入完整训练图 |

到目前为止，我们已经拥有：

```text
✓ Conv
✓ Bottleneck
✓ C2f
✓ C3k2 的当前教学分支
✓ SPPF
✓ P3 / P4 / P5 三尺度特征
✓ FPN 融合
✓ 一个能够前向、反向和保存权重的完整教学模型
```

现在还有一个很明显的问题：

> **所有代码仍然挤在一个 `main.py` 里。**

模型小的时候还能忍，一旦继续加入数据集、Loss、Head、训练器、配置解析和模型构建，这个文件很快就会变成一团乱麻。

所以，第 4 卷，我们不再增加新的网络结构，而是先来一次真正的工程化改造。我们会把现在这个“大杂烩式”的 `main.py` 拆开：

```text
model.py

dataset.py

trainer.py

nn/
├── conv.py
└── block.py
```

让代码从“能跑”进一步走向“能维护、能扩展、能继续长大”。

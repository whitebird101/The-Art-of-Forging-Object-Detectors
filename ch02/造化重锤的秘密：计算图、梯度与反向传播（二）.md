## 2.2 灵石的微观结构 ── 张量维度与形态

在2.1节中，我们理解了计算图和梯度的基本原理。那么，在整个神经网络模型中“流动”的东西到底是什么？答案是：**张量（Tensor）**。

输入图像是张量，模型参数是张量，中间特征是张量，预测结果是张量，Loss 虽然看起来只是一个数字，但它也是张量。

这一节，我们从最基本的标量开始，逐步构建起对四维张量 \[B, C, H, W\] 的完整直觉。

<a id="section-001"></a>
### 2.2.1 灵力本源：理解 Tensor

张量这个词听起来高深，其实可以先粗暴地理解成"多维数组"，它可以是一个数字，也可以是一串数字，也可以是一张表，还可以是一批图像。让我们从低维到高维，逐级攀升：

0维：标量（Scalar）——一粒灵尘

```python
import torch
a = torch.tensor(3.14)
print(a.shape)  # torch.Size([])
print(a.ndim)   # 0
```

一个数字，没有长度、宽度、高度。就像一粒灵尘，微不足道，但万物由它构成。在训练中，最终的 Loss 通常就是一个标量。

1维：向量（Vector）——一串灵珠

```python
import torch
v = torch.tensor([1.0, 2.0, 3.0])
print(v.shape)  # torch.Size([3])
print(v.ndim)   # 1
```

一串数字排成一行，就是向量。就像一串灵珠，用线穿起来。神经网络里的偏置 bias 经常就是向量。比如一个卷积层有 16 个输出通道，那么它可以有 16 个偏置值，每个输出通道分到一个偏置，谁也不抢谁的饭碗。

2维：矩阵（Matrix）——一张灵符

```python
import torch
m = torch.tensor([[1, 2, 3],
                   [4, 5, 6]])
print(m.shape)  # torch.Size([2, 3])  → 2行3列
print(m.ndim)   # 2
```

数字排成行和列，就是矩阵。就像一张灵符，上面刻满了符文。一张灰度图像（无色彩通道）就是一个矩阵。

3维：3D张量——一本灵书

```python
t3 = torch.randn(3, 256, 256)
print(t3.shape)  # torch.Size([3, 256, 256])
print(t3.ndim)   # 3
```

一本书有很多页，每页是一个二维矩阵。一张 RGB 彩色图像就是一个 3D 张量——3 页（红、绿、蓝三个通道），每页 256×256 像素。

4维：4D张量——一箱灵书

```python
t4 = torch.randn(4, 3, 256, 256)
print(t4.shape)  # torch.Size([4, 3, 256, 256])
print(t4.ndim)   # 4
```

四维张量可以想象成一箱书，一箱子装了很多本书。如果每本书是一张RGB图片的话，那么每本书有 3 页，每页是 256×256 的矩阵。当然也可能不止RGB三个通道，可能有几十上百个通道，那么这本书就有几十上百页。

深度学习里，模型通常不是一次只吃一张图，而是一次吃一批图。这一批图像，就叫一个 batch。

所以图像输入模型时，最常见的形状就是四维：

维度升级路线图：

> 标量 → 向量 → 矩阵 → 3D张量 → 4D张量
> 灵尘 → 灵珠串 → 灵符 → 一张彩图 → 一批彩图
> 0维 → 1维 → 2维 → 3维 → 4维

这里要记住两个词：

> ndim：有多少个维度
> shape：每个维度分别有多大

比如：

```python
x = torch.randn(4, 3, 256, 256)
```

那么：

$$
\begin{aligned}
x.ndim &= 4 \\
x.shape &= [4, 3, 256, 256]
\end{aligned}
$$

ndim 告诉你这是几维张量；

shape 告诉你每一维具体是多少。

### 2.2.2 炼宝仙童的打包艺术：拆解 [B, C, H, W]

深度学习中最常见的四维张量格式是 \[B, C, H, W\]。这四个字母分别代表什么？

| **字母** |  **全称**  |    **含义**    |     **类比**     |
|:--------:|:----------:|:--------------:|:----------------:|
|    B     | Batch Size | 一批图像的数量 | 这箱子里有几本书 |
|    C     |  Channels  |     通道数     |   每本书有几页   |
|    H     |   Height   |  高度（行数）  |    每页有几行    |
|    W     |   Width    |  宽度（列数）  |    每页有几列    |

以第1章的输入为例：

```python
images = torch.randn(4, 3, 256, 256)
#                    B  C   H    W
#                    │  │   │    │
#                    │  │   │    └── 每个通道256列
#                    │  │   └─────── 每个通道256行
#                    │  └─────────── 每张图像有3个通道（一张彩色图像通常是RGB三个通道）
#                    └──────────────一批有4张图（一个batch）
```

**1、为什么要有 Batch 这一维？**

也许有人会问：一张 RGB 图像不是 \[3, 256, 256\] 吗？为什么送进模型时变成了 \[1, 3, 256, 256\]？

因为模型通常希望输入永远是“一批图像”。哪怕这一批里只有一张图，也要保留 batch 这一维：

```python
single_image = torch.randn(3, 256, 256)
batched_image = single_image.unsqueeze(0)

print(single_image.shape)   # torch.Size([3, 256, 256])
print(batched_image.shape)  # torch.Size([1, 3, 256, 256])
```

这里的unsqueeze(0)方法的作用，就是在最前面加一个 batch 维度。原来是3维张量\[3, 256, 256\]，加完以后变成4维张量\[1, 3, 256, 256\]。意思是这一批里只有 1 张图。这就像你只买了一本书，也可以装进一个箱子里。箱子不一定要满，但箱子的结构要在。

**2、用索引拆开 \[B, C, H, W\]**

假设：

```python
images = torch.randn(4, 3, 256, 256)
```

我们可以这样理解它：

images\[0\]：取出第0张图像，形状是\[3, 256, 256\]，也就是一本灵书。

images\[0, 0\]：取出第0张图像的第0个通道，形状是：\[256, 256\]，也就是书中的一页。

images\[0, 0, 10, 20\]：取出第0张图像、第0个通道、第10行、第20列的一个像素值。它就是一个标量。

所以 \[B, C, H, W\] 不是抽象咒语，而是一层一层拆得开的：

> 一批图像 → 一张图像 → 一个通道 → 一个像素

**3、为什么是 \[B, C, H, W\] 这个顺序？**

这是 PyTorch 的约定（称为NCHW格式）。PyTorch的Conv2d默认接收 NCHW 格式，底层会根据硬件做优化，所以效率更好。TensorFlow 则默认使用 NHWC 格式（通道放最后），两者本质相同，只是排列方式不同。

目前我们只需要了解：普通图片处理库常见的数据组织格式是 \[H, W, C\]，PyTorch的Conv2d模块默认吃 \[B, C, H, W\]格式的数据，所以基于OpenCV、PIL、NumPy等库读取图片并送进 PyTorch 模型时，经常需要调整维度顺序。比如从 \[H, W, C\]变成\[C, H, W\]，再加上 batch 维度，得到\[B, C, H, W\]形状的数据（张量），这一步后面做真实数据集时会反复遇到。

**4、经过网络层之后，张量的形状会怎么变？**

可以用一个粗略的规律来描述张量在不同网络层中形状的变化：标准 Conv2d 通常不改变 B，也就是不改变批次大小，——卷积层不关心你送了几张图，它逐张处理。输出通道数C由卷积层的参数out_channels决定，H 和 W 是否改变，取决于卷积层的空间参数设置。

比如nn.Conv2d(3, 16, kernel_size=3)，它的意思是输入通道数是3，输出通道数是16，所以它会把通道数从C = 3变成C = 16。也就是说，输入张量的形状如果是\[B, 3, H, W\]，输出就会变成类似\[B, 16, 新H, 新W\]。这里的新H和新W具体变成了多少，暂时先不要急着。它们和卷积层的卷积核大小、步幅、补边等设置有关，也就是后面会遇到的kernel_size、stride、padding等参数。这些名字现在先混个脸熟即可。至于卷积层如何让H和W变大变小或保持不变，后面拆 Conv2d 的时候，再详细说明。
